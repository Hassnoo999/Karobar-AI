# Karobaar AI frontend

The frontend presents Karobaar as a simple merchant workflow instead of accounting software. It supports desktop and mobile screens for capturing transactions, checking the ledger, asking business questions, and reviewing financial evidence.

## Main routes

| Route | Purpose |
|---|---|
| `/` | Public product story and hackathon landing page |
| `/signin` and `/signup` | Supabase authentication when configured |
| `/dashboard` | Monthly sales, expenses, udhaar and recovery overview |
| `/record` | Voice, receipt or manual entry → editable review → explicit confirmation |
| `/ledger` | Transactions/customers, search, source/type/aged-unpaid filters, pagination and filtered CSV |
| `/ask` | Five deterministic ledger tools plus reviewed, cited financing facts; no loan decisions |
| `/evidence` | Evidence metrics, financing references and an editable, copyable reminder |
| `/financing` | Phase 2: researched program details, temporary applicant declarations, preparation comparisons and cited questions |

## Local setup

Use Node.js 22.x (the runtime declared in `package.json`).

```powershell
npm ci
Copy-Item .env.local.example .env.local
npm run dev
```

Open `http://localhost:3000`. The FastAPI backend should run at `http://localhost:8000`.

For a loopback-only development workspace, leave the two Supabase values empty and open `/dashboard` directly. The backend must use `REQUIRE_AUTH=false` locally; this is not a sign-in simulation. For every shared deployment, configure both values and enable `REQUIRE_AUTH=true` in the backend.

```env
NEXT_PUBLIC_API_BASE_URL=http://localhost:8000/api
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
```

## Data behavior

- Product screens share one `/api/combined` snapshot. Confirmation and Refresh reload it; changing accounts clears the snapshot and remounts private drafts/chat state.
- Customer balances and evidence figures come from full-history backend aggregates, not the latest 200 loaded entries.
- Ledger pagination and entry filters/export apply to the loaded window; a notice appears when older entries are not loaded.
- Network errors never substitute sample figures or chatbot answers. The sample preview has been removed; users retry the real connection instead.
- When Supabase is configured, protected routes wait for the restored session and redirect unauthenticated visitors to `/signin`.
- Signup opens the dashboard only when Supabase issues a session. If email confirmation is required, the page tells the user to check email and return to sign in; it does not pretend an unconfirmed account is signed in.
- The frontend preserves missing fields, zero/unknown confidence, duplicate flags and source labels. Provider metadata stays available for diagnosis without displaying provider names in receipt review. Invalid drafts cannot be confirmed; failed saves retain the draft.
- Manual entry uses the same confirmation/accounting path and carries no invented AI confidence.
- Voice and receipt uploads are capped at 4 MB. Use short recordings; larger direct uploads are not implemented in this release.
- Voice/receipt capture rejects Demo AI drafts. Real-provider failures distinguish quota, busy service, timeout, configuration and unusable output. Retry keeps the selected file; manual entry remains available. JPEG, PNG and WebP are supported; export HEIC first.
- Review shows the transcript and AI uncertainty notes, not provider names. Receipt sender/recipient/purpose fields are retained: received/sent selection fills the opposite party's editable name. Missing dates/types remain editable and block confirmation; incoming transfers are not assumed to be udhaar repayments.
- Receipt drag-and-drop and the chooser share one-photo/type/size validation. Active review cannot be overwritten; server image-byte validation remains authoritative.
- Recording chooses a supported browser MIME/container, handles microphone errors and rejects empty/very short recordings. Decodable digital silence is checked before upload; real-room/dialect quality still requires human rehearsal.
- The evidence passport retains reference links. The Phase 2 financing workspace adds dated published facts and comparisons against user declarations, not eligibility predictions. Sales and expense figures are current-month ledger context, never invented qualification thresholds.
- Ask uses rule-based interpretation for recognized questions and guarded model classification for remaining financial paraphrases. Financial wording is rendered from ledger values, not generated by a model. Daily sales, expenses, profit, historical customer balances and loan qualification are not chat tools.
- Reminder copy is awaited and editable; copying never sends a message.

## Phase 2 local checkpoint — 23 October 2026

The new financing page follows the existing forest/mint theme, with CSS-only floating proof cards, progress bars, institution search and native blurred-backdrop dialogs. Motion respects reduced-motion preferences. Applicant answers are kept only in page memory and reset on navigation/account change; no CNIC numbers or bank account details are collected. Editing declarations clears old financing answers so a previous comparison cannot look current.

Scheme Q&A retrieves a small, reviewed catalogue. The optional AI relevance assist can select only retrieved fact IDs; the server renders the actual facts and citations. An unavailable or invalid model response leaves the reviewed source answer available. This is curated retrieval with optional LLM selection, not a vector database or an unconstrained financial adviser. Source facts remain English, with English/Roman Urdu/Urdu question matching; full translated answers are not claimed.

This is a local `phase-2` checkpoint, not a new public release. See [Phase 2 plan, verification and rehearsal](../docs/PHASE_2.md) before publishing. Production authentication and deployment settings are unchanged.
